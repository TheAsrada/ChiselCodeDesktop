# Правила проекта

- Работайте в `main`; сохраняйте чужие изменения. Не создавайте ветки или PR без указания владельца.
- Ядро, инструменты, разрешения, провайдеры, миграции и desktop-протокол принадлежат TheAsrada/ChiselCode. Не копируйте их реализацию в этот репозиторий.
- Обновляйте ядро через `engine.lock.json` и `scripts/sync-engine.mjs`; выполняйте handshake и проверки установленных сборок.
- Renderer работает без Node.js и не получает ключи, shell или прямой доступ к файлам. Native API ограничен preload-контрактом.
- UI показывайте настоящими кадрами приложения с реальным ядром. Состояния ошибок, отмены и подтверждения являются частью рабочего сценария.
- Пишите пользовательские тексты, документацию, CHANGELOG и release notes по-русски.
- Не отмечайте возможности или платформы проверенными без фактического прогона. Обновляйте документацию и CHANGELOG вместе с поведением.

## Оформление и тексты

- Перед изменением UI прочитайте [руководство по дизайну](docs/design.md): референсы владельца, композиция, палитра и настоящие кадры. Сохраняйте собственный знак Chisel, плавающую навигацию и иерархию рабочих поверхностей; изменение общего направления требует поручения владельца.
- Пишите названия действий, фактические данные, ошибки и состояния операций. Не добавляйте приветственные обещания, слоганы и нейросетевые пояснения вроде «готов к работе», «изменения под вашим контролем» или «проверяйте diff». Подсказки добавляйте только для конкретного действия или его последствий.
- При изменении оформления проверяйте обе темы, клавиатурный фокус и компактное окно. Сохранённая тема, проект, беседа и черновик должны переживать навигацию; новая тема по умолчанию не заменяет прежний выбор пользователя.

## Синхронизация с CLI и совместный релиз

- До изменений прочитайте `AGENTS.md` и `docs/contributors/desktop-sync.md` в соседнем ChiselCode. [Общий порядок](https://github.com/TheAsrada/ChiselCode/blob/main/docs/contributors/desktop-sync.md) обязателен для обоих проектов. Если checkout отсутствует, получите его в отдельную соседнюю папку на `main`, сохраняя существующие данные; при отсутствии доступа явно сообщите блокировку.
- Любое добавление или исправление оценивайте для обеих оболочек. Не откладывайте необходимую правку core/adapter/SDK на отдельное задание. Общую логику исправляйте в ChiselCode; здесь адаптируйте клиент и проверяйте реальный сценарий. При отсутствии влияния на CLI укажите причину.
- Обновляйте затронутую документацию и `Unreleased` обоих проектов. До core release различайте готовую интеграцию в исходниках и ожидающее обновление встроенного ядра. Не закрепляйте фиктивные manifests/hashes и не публикуйте выпуск только ради lock без просьбы владельца.
- Просьба владельца «сделать релиз» по умолчанию поручает выпустить **CLI и Desktop** без дополнительного согласования второго выпуска. Исключение — явная просьба выпустить только один проект. Сначала проверенный CLI release с engine/SDK/skills/manifest, затем `npm run update:engine -- v<версия-CLI>`, `npm run sync:engine`, `npm ci`, клиентские правки, проверки и Desktop release с этим ядром.
- Версии UI и CLI независимы; сохраняйте текущий prerelease-канал до явного изменения владельцем. Создавайте новые tags только после успешной native CI-матрицы на выбранных release source commits. Для Desktop обязательны реальный GUI и установленные payload на Windows x64, Linux x64 и macOS arm64/x64.
- Не передвигайте tags и не заменяйте опубликованные assets. При сбое второй публикации продолжайте исправление; совместный релиз завершён только после публикации обоих проектов. В финальном отчёте укажите обе версии, встроенный engine/source, ссылки на оба выпуска, проверки и ограничения.
