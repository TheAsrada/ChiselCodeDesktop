# Первый запуск

Откройте папку проекта кнопкой **Открыть проект**. Если CLI уже использовался, его профили будут доступны. Иначе откройте настройки, выберите провайдера, API-адрес при необходимости, модель и ключ. Кнопка проверки получает список моделей по сохранённому профилю; новый профиль сначала нужно сохранить.

## Рабочий цикл

1. Выберите **Plan**, чтобы изучить проект и получить предложение без изменений.
2. Переключитесь на **Build** для выполнения. По умолчанию изменения и команды требуют подтверждения.
3. Проверьте команду/файлы в окне подтверждения, затем разрешите один раз или отклоните.
4. Посмотрите результат и Git diff в панели справа. История сохранится и будет видна в CLI.

Пример первой задачи: «Изучи структуру проекта и объясни, где запускаются тесты». Новая беседа создаётся при отправке первого сообщения. Между беседами можно переключаться, пока агент работает. Сообщение активной беседе становится в очередь с текущей моделью и режимами. Остановка очищает её очередь и отменяет текущую foreground задачу и помощников.

## Разрешения

- **Подтверждать** — запрос на изменения/команды.
- **Разрешать правки** — workspace edits автоматически, процессы/Git/другие effects отдельно.
- **Без запросов** — действия, которым нужно подтверждение, отклоняются.

Выбор применяется к следующему отправленному запросу. Он не меняет разрешения уже выполняющейся задачи. В первой beta Bypass не предлагается графическим клиентом. Shell использует права вашего пользователя, как в CLI.

## Клавиатура

| Действие | Клавиши |
|---|---|
| Отправить | Enter |
| Новая строка | Shift+Enter |
| Plan/Build в поле ввода | Shift+Tab |
| Новая беседа | Ctrl/⌘+N |
| Настройки | Ctrl/⌘+, |
| Закрыть окно настроек/просмотра | Esc |

MCP настраивается в отдельной вкладке настроек. Проверка HTTP/stdio запускает указанный сервер, затем сохраняет подключение через общий controller. Навыки и foreground команды доступны в разделе Контекст справа; нажатие переносит команду в поле ввода для проверки аргументов.
